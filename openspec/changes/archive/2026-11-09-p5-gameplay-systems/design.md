## Context

P2 建立战斗竖切，P4 提供联机。第一版玩法闭环还缺技能/英雄/物品/经济/生产/科技/胜负。上游 `rts_kernel_cs` 的 `RTS_ABILITY_SYSTEM.md` 给出三层扩展（模板 / 效果组合 / 注册行为）、冻结定义、运行态与内容哈希契约，可借鉴；WC3 的 JASS 触发器 VM 不在第一版范围（ADR 0003）。

## Goals / Non-Goals

**Goals:** 玩法闭环可玩；所有新增系统状态进入哈希与快照；AI 重放不双重执行。

**Non-Goals:** JASS / wtg 触发器 VM；自定义地图；Mod API；配置热更新；跨版本存档迁移；战争迷雾/隐身反隐。

## Decisions

- **D1 三层技能扩展**：模板处理常见流程，效果组合复用已有效果，特殊机制按行为 ID 注册。
  - **备选方案（Alternatives considered）**：*脚本 VM* — 否决（引入不确定执行顺序与额外运行时，且 ADR 0003 明确不做 JASS）；*行为树框架* — 否决（引入独立调度层与运行态，超出第一版范围）；*任意表达式语言* — 否决（无法保证跨平台确定性）；*三层扩展（模板 / 效果组合 / 注册行为）* — 采纳，扩展点收敛在行为 ID，规则仍在 `w3-core` 内。
  - **关联 ADR 0002 与跨平台确定性影响**：技能 / Buff / 冷却 / 效果链运行态全部进入 FNV-1a 状态哈希与帧提交后的完整快照（ADR 0002 §6、§7）；效果按稳定顺序结算，不引入浮点或异步完成顺序。本决策不新增可比较的算术来源，跨平台确定性仍为待验证项（目前仅 Windows / rustc 1.91 实跑），不得据本设计声称已达成。
  - **架构原则与分层依赖**：SRP（模板 / 组合 / 注册各司其职）、OCP（按行为 ID 扩展而不改内核）、唯一状态所有者（`RtsMatch`）。`w3-core` 不反向依赖 `w3-content` / 上层 crate。

- **D2 冻结定义 + 内容哈希**：SLK 表经内容层转换成冻结定义，哈希进快照头；对局中禁止热更新。
  - **备选方案（Alternatives considered）**：*运行时读表* — 否决（同一对局内定义可变，破坏重放一致性）；*配置热更新* — 否决（ADR 0003 明确不做）；*冻结定义 + 内容哈希进快照头* — 采纳，定义冻结为对局配置的一部分，恢复时校验。
  - **关联 ADR 0002 与跨平台确定性影响**：内容哈希进入快照头部，版本 / `sim_version` / 内容哈希不匹配 MUST 拒绝恢复（ADR 0002 §7）；冻结定义使用整数 / 字符串 / 布尔，上游浮点数值列在边界拒绝（ADR 0004），不把 `f64` 混入模拟，故不新增跨平台浮点差异来源。原始导出数据留在玩家本机、不入库（ADR 0001）。
  - **架构原则与分层依赖**：DIP（`w3-core` 依赖冻结定义接口而非内容层）、冻结输入边界（`w3-content` 只做纯读取器）；`w3-core` 零反向依赖。

- **D3 统一结算服务**：生命/法力、伤害、治疗、Buff、属性修正与目标过滤由单一所有者处理，费用提交事务与效果执行链分离。
  - **备选方案（Alternatives considered）**：*技能各自改血* — 否决（多个写者导致顺序竞争与遗漏哈希字段）；*每个系统独立结算器* — 否决（口径漂移、差异定位困难）；*统一结算服务 + 费用事务 / 效果链分离* — 采纳。
  - **关联 ADR 0002 与跨平台确定性影响**：所有改血 / 改属性路径收敛到唯一所有者，保证相同命令脚本下逐帧 `compute_state_hash()` 相等、`first_difference()` 可定位（ADR 0002 §5、§6）；后续效果在目标死亡后返回 `NoEffect`、不回滚不重复扣费，是可复现的稳定顺序行为，不依赖平台浮点或线程调度。
  - **架构原则与分层依赖**：SRP / 唯一状态所有者 / LoD（调用方只见结算接口，不直接改运行态字段）。

- **D4 AI 命令同源**：玩家与 AI 走同一 `submit_command` / 玩法命令校验入口，内部 AI 命令不写回命令队列，重放只注入外部命令。
  - **备选方案（Alternatives considered）**：*把内部 AI 命令再次注入重放* — 否决（重放双重执行、逐帧哈希漂移）；*为 AI 单开一条校验入口* — 否决（玩家 / AI 口径漂移，违反同源）；*AI 命令覆盖仍有效的玩家命令* — 否决（破坏命令排序与可预期性）；*同源校验 + 每帧确定性重算、内部命令不注入* — 采纳。
  - **关联 ADR 0002 与跨平台确定性影响**：命令仍按 `ExecuteFrame → PlayerId → Sequence → Arrival` 稳定排序（ADR 0002 §3）；AI 每帧确定性重算、内部命令不入队，使「重放只注入外部玩家命令」与原始对局逐帧哈希一致，不引入墙钟 / 线程完成顺序依赖。AI 状态与定时任务进入状态哈希与快照（ADR 0002 §6、§7）。
  - **架构原则与分层依赖**：唯一状态所有者、ISP（AI 与玩家共用窄校验接口）；`w3-core` 不依赖表现层 / 网络层。

## Risks / Trade-offs

- [权威状态大幅扩张] → 每个新系统 MUST 同步扩展哈希、快照与差异定位；用 `tests/determinism.rs` 作为门禁。
- [第一版不含自定义地图] → 与"完整复刻"存在差距，README 与对外表述须如实说明。
- [Q47.16 对经济/时长数值的精度] → 引入前核算范围，必要时换 Q 格式。
- [20,000 单位目标与三层效果链的性能] → 未验证，列为远期评估。

## Migration Plan

扩展 `RtsMatch` 内部模块与状态字段；新增内容定义层；`tests/determinism.rs` 增加施法、Buff 到期、同帧死亡、生产取消场景。

## Open Questions（已结案）

以下两项在 P5 实现中已有答案，归档前结案，不再作为待决项：

- **SLK 表到冻结定义的字段映射与默认值口径 — 已结案**：答案在 `crates/w3-content/src/definitions.rs` 模块文档。字段为内容层自定义的规范化合成列名（单位 / 技能 / 物品 / 升级四张规范表，均为合成口径）；所有非主键字段采用唯一、零例外的机械默认值——键缺失或值为 `null` 时数值取 `0`、字符串取 `""`、布尔取 `false`，缺失与 `null` 同口径；上游浮点数值列（如 `1.5`）在边界被拒绝，不截断、不四舍五入（ADR 0004）。主键缺失 / 空串 / `null` 返回 `DefinitionError::MissingId`；内容层刻意不臆造游戏平衡默认值，语义补全交由 `w3-core` 规则。
- **AI 内部命令的诊断日志格式与重放模式标识 — 已结案**：答案在 P5 实现（`crates/w3-core/src/gameplay.rs`、`crates/w3-core/src/sim_match.rs`）。玩家与 AI 共用 `validate_gameplay_command` 同一校验入口（与 `submit_gameplay_command` 同源）；AI 每帧确定性重算，内部命令不写回玩法命令队列、不注入重放；完整重放只注入外部玩家命令，因此不会双重执行内部 AI 命令；诊断日志一律英文结构化 `key=value`（CODEBUDDY.md §3）。**第一版不设独立重放模式标识**——这是明确的设计取舍：重放以「只注入外部命令 + 同源校验 + AI 确定性重算」即可逐帧一致，额外模式标识会新增需进入哈希 / 快照的权威状态字段，收益不抵复杂度；如将来引入独立重放模式，MUST 按 ADR 0002 同步扩展状态哈希与快照并先让 `tests/determinism.rs` 通过。
