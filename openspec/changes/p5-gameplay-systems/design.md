## Context

P2 建立战斗竖切，P4 提供联机。第一版玩法闭环还缺技能/英雄/物品/经济/生产/科技/胜负。上游 `rts_kernel_cs` 的 `RTS_ABILITY_SYSTEM.md` 给出三层扩展（模板 / 效果组合 / 注册行为）、冻结定义、运行态与内容哈希契约，可借鉴；WC3 的 JASS 触发器 VM 不在第一版范围（ADR 0003）。

## Goals / Non-Goals

**Goals:** 玩法闭环可玩；所有新增系统状态进入哈希与快照；AI 重放不双重执行。

**Non-Goals:** JASS / wtg 触发器 VM；自定义地图；Mod API；配置热更新；跨版本存档迁移；战争迷雾/隐身反隐。

## Decisions

- **三层技能扩展**：模板处理常见流程，效果组合复用已有效果，特殊机制按行为 ID 注册。否决脚本 VM、行为树框架、任意表达式语言。
- **冻结定义 + 内容哈希**：SLK 表经内容层转换成冻结定义，哈希进快照头。否决运行时读表或热更新。
- **统一结算服务**：生命/法力/Buff/属性修正由单一所有者处理。否决技能各自改血。
- **AI 命令同源**：玩家与 AI 走同一 `submit_command` 入口；重放只注入外部命令。否决把内部 AI 命令再次注入重放。

## Risks / Trade-offs

- [权威状态大幅扩张] → 每个新系统 MUST 同步扩展哈希、快照与差异定位；用 `tests/determinism.rs` 作为门禁。
- [第一版不含自定义地图] → 与"完整复刻"存在差距，README 与对外表述须如实说明。
- [Q47.16 对经济/时长数值的精度] → 引入前核算范围，必要时换 Q 格式。
- [20,000 单位目标与三层效果链的性能] → 未验证，列为远期评估。

## Migration Plan

扩展 `RtsMatch` 内部模块与状态字段；新增内容定义层；`tests/determinism.rs` 增加施法、Buff 到期、同帧死亡、生产取消场景。
