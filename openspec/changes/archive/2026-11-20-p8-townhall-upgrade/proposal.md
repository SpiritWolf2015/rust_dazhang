# Proposal

## Why

落实路线图 `docs/roadmap/P8-human-orc-melee.md §3 P8.5`（:119-131）的 **P8.5b「主城升级」**（:126 表行「主城 Keep / Stronghold 升级、解锁二线单位与科技」、验收「升级后训练 / 解锁生效，快照哈希稳定」）；P8.5 全量已由用户 2026-11-14 拍板必做（:28 / :151），五个子系统各单独 change、串行推进、不塞回 P8.0–P8.4（:121 / :30），P8.5a 英雄复活已于 2026-11-20 归档、本 change 紧接。用户 **2026-11-20 经 `AskUserQuestion` 明确拍板方向 A「独立 tier 状态」**（锚：本会话用户消息 / leader 转达，非仓库文件、由人工核对，按 `openspec/decision-memo.template.md` 三分判据第 3 类标注、不冒充已落库文档）：新增「主城等级 / tier」**顶层权威状态**，按 ADR 0002 全流程进入 FNV-1a 状态哈希、由 `SNAPSHOT_VERSION` 定义的快照与 `first_difference()`，升级与解锁在 `w3-core` 确定性命令面生效，HUD 只读派生。现状内核无 tier 权威状态（C2）、无升级命令（C3）、训练 / 研发全量可训练无前置判据（C4 / C5）、HUD 无 `U` 升级格位（C6），故被否备选 A′「复用 `PlayerEconomy.upgrades` 布尔旗标 + 静态 tier 表」与 B「表现层只读派生假升级」均达不到验收线「升级后训练 / 解锁生效、快照哈希稳定」（详见 `decision-memo.md` P1 /「## 被否方向台账」与 `design.md` D1）。业务规则依据 `docs/references/WC3-MELEE-RULES.md`：**R4.1**（城镇大厅可升级两次 T1→T2→T3、逐级解锁建筑与科技、主基地摧毁影响胜负 R11，正文 :141，**附录表 :362 的 `R4.1 :137` 为旧行号、本 change 只引用规则编号**）、**R4.3 / R4.4**（生产 / 研发建筑、解锁生效）、**R1.2 / R13.3**（定义层数据驱动、禁建筑名字符串白名单）、**R13 / R13.2 / R13.7**（`U` 主基地升级与命令卡）、**R3.1**（资源结算）、**R11**（胜负）、**R12.4**（回放哈希一致）、**§14**（不静默改规则、`[待核]` 数值不冒充经典）、**§0** 的 1.0 范围 **S1**（局域网联机对战，含真人 VS AI 敌人玩家）/ **S2**（回放）/ **S3**（四族功能做完）。不做范围 N1–N6 不纳入。相关 ADR：**0001**（零资产 / 许可证）、**0002**（确定性硬门禁）、**0003**（范围与分期）、**0004**（冻结坐标）、**0005**（联机线格式与 protobuf 分层边界）。

## What Changes

- **新增顶层权威状态并纳入确定性契约**：在 `w3-core` 新增「主城等级 / tier」顶层权威状态（每个玩家的主城实体关联离散等级 T1/T2/T3，独立状态、MUST NOT 复用 `PlayerEconomy.upgrades` 的 `BTreeMap<DefId, bool>` 布尔科技旗标，C5），全部 MUST 同步进入 FNV-1a 状态哈希、由 `SNAPSHOT_VERSION` 定义的快照与 `first_difference()`（ADR 0002 §6-8 / `CODEBUDDY.md §5`）。30 Hz 整数帧、`ExecuteFrame → PlayerId → Sequence → Arrival` 稳定排序键、稳定 `EntityId` 顺序不变。
- **定义层 tier 需求链与冻结常量**：升级费用 / 时间（整数帧）/「tier → 解锁二线单位与科技需求链」按 Q3 推荐落 `FrozenDefinitions` 冻结常量，经 `compute_defs_hash` 进入 `defs_hash` / `content_hash` 快照头部（C4）；全为合成 / 原创编译期整数常量、`[待核]`、由定义层类别与需求链数据驱动、MUST NOT 用建筑名字符串白名单或硬编码 DefId（R1.2 / R13.3 / ADR 0001 / ADR 0004 / §14）。tier **权威状态**与 tier **需求链冻结常量** MUST 明确区分（后者属定义层内容变化、非新增权威状态字段）。
- **升级命令与事实事件**：按 Q2 推荐新增独立 `GameplayCommandKind::UpgradeTownHall` 变体（指定主城实体 + 目标 tier）+ 升级开始 / 完成 / 取消事实事件，经公开提交入口按冻结整数帧号入队、同源校验、稳定排序；牵动 `hash_gameplay_command` 编码（现 1–12 → 追加 13）、命令校验 / 穷尽分发、`EventKind`、ADR 0005 protobuf 字段编号只追加（`reserved 14 to 32` 不变）/`PROTOCOL_VERSION` bump / `Reject` 明确拒绝旧版本 / canonical 约束 / CI 双平台生成代码字节一致，`net-owner` 按 `CODEBUDDY.md §9` 与 `sim-owner` 串行协作（C3 / C21 / C20 条件命中 T6）。复用 `Research` + 扩展 `UpgradeDef` 为被否备选。
- **训练 / 研发解锁判据**：`enqueue_production` / `research` 按冻结 tier 需求链增加前置判据，未达 tier 的二线单位 / 科技 `Train` / `Research` MUST 显式拒绝、不静默放行；升级完成后解锁立即在 `w3-core` 确定性命令面生效（R4.1 / R4.3 / R4.4 / 验收 :126）。MUST NOT 复用「全量可训练」旧行为（C4）。
- **费用事务与退款**：升级扣费提交与队列效果执行 MUST 分离（主 `openspec/specs/gameplay-systems/spec.md:19`），提交前校验 gold / lumber 充足再冻结扣费登记；取消 / 主城被毁 / 对局失败 MUST 事务性退款、MUST NOT 静默丢队列 / 重复扣费 / 半升级；资源不足 MUST 显式拒绝、不静默免费升级（显式失败不静默降级）。升级费用 / 时间 / 差价全为合成原创 `[待核]` 常量、MUST NOT 把导出总价直接当扣款（`CLASSIC_RULES_BASELINE.md:46`）。
- **表现层 HUD 只读派生**：`U` 键与命令卡主城升级格位、升级进度 / 费用 / 剩余帧只从只读 `Snapshot` + 事实事件派生（复用 P8.5a `ReviveHudModel::derive(snapshot, events)` 范式，C6），MUST NOT 反写权威状态 / 进状态哈希 / 快照 / `first_difference()`（ADR 0002 §5）；键位与格位由定义层数据驱动、`[待核]` 具体绑定不入库、不写死建筑名白名单（R13 / R13.2 / R13.3 / R13.7）。
- **主 specs 口径同步修订**：用 `## MODIFIED Requirements` delta 覆盖 `faction-definitions` / `melee-match` / `human-faction` / `orc-faction` / `gameplay-systems` / `command-hotkeys` 中含「`w3-core` 零 diff / `SNAPSHOT_VERSION` 仍 3 或 4 / golden hash 逐字节不变 / 命令与效果类型集合不变 / MUST NOT 新增权威状态」等与方向 A 冲突的规范性 requirement，逐字保留历史 `#### Scenario:` 身份键、口径改在 THEN、requirement 正文给完整新正文（B-1 教训，C9）；归档时才合并，本阶段不改主 `openspec/specs/**` 正文。其余含同类历史口径的主 specs 与所有 `## Purpose` 概述文字经实测 OpenSpec 1.17.0 delta 不合并，如实登记为已知限制由 `docs-owner` 后续独立 change 收口，不冒充已消除（Q5）。
- **BREAKING**：`SNAPSHOT_VERSION` 按 Q1 推荐 bump **4→5**（连同 `SIM_VERSION`、快照头部、单测硬断言 `sim_match.rs:2368-2369`、golden hash 基线、主 specs 口径、ADR 0002 复核记录追加；旧 v4 快照 / 回放按 `SnapshotError` / `Reject` 明确拒绝、不提供跨版本迁移）；golden hash 基线按新实现如实更新、必变、不沿用 P8.5a v4 值；新增 tier 权威状态 MUST 完整进哈希 / 快照 / `first_difference()` 并跑通 determinism 26 项 +「改坏验红」；主 specs 旧「零 diff / 仍 3 / 逐字节不变」口径失效、由本 change 的 MODIFIED delta 同步修订。
