# ADR 0003：项目范围与分期（Melee 优先）

- **状态**：Accepted（2026-11-14 部分修订：战争迷雾 / 隐身纳入 1.0；2026-11-25 部分修订：明确长期目标为像素级复刻 War3、引入 clean-room 反编译证据流程试点；2026-11-27 部分修订：p18 承接「机制全量 + 三版本号 9→10 全套契约」，见文末「修订记录」）
- **日期**：2026-11-07（决策）/ 2026-11-14（修订）
- **相关**：[ADR 0001](0001-license.md)、[ADR 0002](0002-determinism.md)；`README.md` 范围表

## 背景（Context）

目标是"用 Rust 复刻经典 RTS"，但"复刻"可以指从 Melee 对战一直到含 JASS 自定义地图的完整生态，后者规模远超小团队可交付范围。三个参考项目恰好都在这条线上留了空白：

- `vera20k`：完整复刻 `gamemd.exe` 的 RA2 玩法与联机，但全部绑死 RA2 数据 / 资产 / 2D 渲染，无可移植的游戏逻辑抽象层。
- `godot_warcraft3`：有成熟的 WC3 资产 / 数据管线（MPQ → SLK JSON → BLP/MDX → 地图 JSON），但触发器 / JASS 列为远期 `N∞`（`docs/roadmap/NEXT.md:35`），联机未实现。
- `rts_kernel_cs`：纯 C# 模拟内核契约与移动 / 寻路语义，但明确"网络通信、完整移动规则、战斗、经济、技能等仍有待开发"（`README.md:7`），且不承诺跨平台确定性。

结论：**三者都没有 JASS / 触发器 VM，也都没有可直接搬用的 WC3 战斗 / 经济 / 技能实现**。第一版必须主动收缩范围，否则会卡在最大的空白上。

## 决策（Decision）

### 目标

第一版交付：**确定性模拟内核 + 命令帧同步联机 + Melee 对战**（不含自定义地图脚本）。玩法、数据与资产兼容性以"玩家自备正版经典客户端"为前提（合规边界见 [ADR 0001](0001-license.md) 与 `README.md` 免责声明）。

### 分期

| 阶段 | 交付 | 状态 |
|---|---|---|
| P0 | 定点数、整数帧、实体 ID、命令队列、状态哈希、快照、三类确定性验收 | **已完成**（commit `d7a4e19`） |
| P1 | 读 `godot_warcraft3` 导出的 `slk-exported/` 与 `map-parsed/` JSON，加载一张地图的地形与摆放；**过渡期不写 Rust 原生 MPQ / SLK / MDX 解析器** | **已完成**（归档 `2026-11-07-p1-content-import`） |
| P2 | 模拟竖切：选中 → 移动 → 攻击；移植八方向寻路、动态障碍、朝向 / 坡度、群体编队语义，并换成 [ADR 0002](0002-determinism.md) 的定点数学 | **已完成**（归档 `2026-11-08-p2-simulation-vertical-slice`；坐标契约见 [ADR 0004](0004-frozen-coordinates.md)） |
| P3 | wgpu 3D 渲染：glTF / MDX 骨骼动画、高度场地形、队伍色、粒子 / 挂点（转换规格取自 `godot_warcraft3/docs/design/asset-convert/`） | **已完成并归档**（归档 `2026-11-08-p3-wgpu-3d-renderer`，主 `3d-rendering` spec 已更新） |
| P4 | 移植 lockstep + UDP 可靠层 + 自建 lobby / relay；双客户端同图对战、逐帧 checksum 对比 | **已完成并归档**（归档 `2026-11-08-p4-lockstep-networking`；双客户端逐帧哈希一致，真实 UDP 双进程实机验收通过，主 `lockstep-networking` spec 已更新） |
| P5 | 技能 / 英雄 / 物品 / 科技 / 经济 / 采集 / 建造 / 生产 / 胜负（契约参考 `RTS_ABILITY_SYSTEM.md` 的三层模板 + 效果组合） | **已完成并归档**（commit `d9f5321`，13/13 tasks，已 push；归档 `2026-11-09-p5-gameplay-systems`，主 `gameplay-systems` spec 已建立） |
| P6 | 可玩客户端集成层（交互 / UI / 固定 30 Hz 步进 / 联机 session 接入）：复用既有 `winit 0.30` + `wgpu 30` + `w3-render`，补齐输入→命令、HUD、交互相机与本地 / 联机共用呈现管线；**集成收尾，不新增玩法阶段**（见 change `p6-playable-client`） | **已完成并归档**（归档 `2026-11-10-p6-playable-client`，主 `playable-client` spec 已建立；54/55 tasks，9.9 归档已执行；commit `f5c0555` 已 push） |

### 明确不做（第一版）

- **不引入通用游戏引擎（Bevy 等）**：其 ECS 自动并行调度、异步系统完成顺序与 `f32` / `f64` `Transform` 会与 [ADR 0002](0002-determinism.md) 的整数帧、稳定 `EntityId` / 命令排序、定点权威状态（禁止浮点进入权威状态 / 快照 / 状态哈希）直接冲突；可玩客户端复用既有 `winit 0.30` + `wgpu 30` + `w3-render`，至多加一个轻量 UI 依赖（见 change `p6-playable-client` 的 D1）。
- **JASS / wtg 触发器 VM、自定义地图、战役与过场**：三者皆无实现，属独立大工程；须单独立项后再开 ADR。
- 战争迷雾 / 隐身反隐体系：后续单独机制，不挤进第一版。（**本条已被 2026-11-14 修订 supersede**：1.0 改为纳入，见文末「修订记录」；原文保留以存决策历史。）
- Mod API、配置热更新、跨版本存档迁移、跨运行时（.NET / Godot）兼容。
- 与官方战网 / BNET 兼容；联机只走自建 lobby / relay。
- Godot 宿主、GDScript、Node 场景树；本项目为 Rust + wgpu / winit 自研。
- 原生 `gamemd.exe` 的 Event 线格式（那是 `vera20k` 的 RA2 协议，不复用）。
- 任何暴雪资产的提交或分发。

### 规模与帧率

- P0–P2 以 **10 名玩家 / 300 活跃单位**为验证规模（沿用 `rts_kernel_cs` 的保守起点，`RTS_KERNEL.md:14`）。
- **20,000 单位 / 30 玩家**是 `vera20k` 展示的远期规模目标，**不在第一版承诺**；若要提升，需按 [ADR 0002](0002-determinism.md) 复核点重新做性能与确定性验证，并评估 data-oriented 改造。
- 逻辑帧率 **30 Hz** 已由 ADR 0002 冻结；变更需新 ADR + 全量重放验证。
- 地图 / 单位上限等由内容数据决定，不硬编码进内核。

### 合规

沿用 `godot_warcraft3` 与 `vera20k` 一致的模型：仓库只提交工具与解析代码；MPQ 及其派生文件（含导出的 SLK / 地图 JSON、PNG / GLB / 音效）一律不入库；运行时按 `config.toml` 的本机路径读取。项目名 `rust_dazhang` 为原创通用词，`README.md` 带免责声明。

## 备选方案（Alternatives considered）

| 方案 | 结论 | 理由 |
|---|---|---|
| 第一版即完整复刻（含 JASS / 自定义地图 / 战役） | 否决 | 三个上游都没做触发器 VM；WC3 的 3D + JASS 复杂度显著高于 RA2 2D，范围不可控。 |
| 直接 fork `vera20k` 改造成 WC3 | 否决 | 165 万行中约 97% 绑死 RA2（gamemd 地址、INI、SHP/VXL、2D 渲染、retail 校验），且 GPLv3 附加条款随之进入。 |
| 继续用 Godot 宿主 | 否决 | 目标已定为 Rust 自研引擎；Godot 项目只作为格式规格与导出数据来源。 |
| 先写全套 Rust 原生格式解析器 | 暂缓 | P1 先读现成导出 JSON 让核心跑通，站稳后再逐个替换——这是三个项目之间唯一现成可对接的数据接口。 |

## 后果（Consequences）

**正面**：范围可交付、每阶段有明确验收；P0 已建立确定性基线；合规边界清晰；三个上游各取所长而不背其技术债。

**负面 / 需明确接受**：

- 第一版**不能运行原作自定义地图**，与"完整复刻 WC3"存在明显差距；需在 `README.md` 与对外表述中如实说明。
- P1 依赖 `godot_warcraft3` 的导出 JSON 作为外部输入，其 schema 变化会影响本项目；该依赖须在 P1 记录版本与本地路径（`docs/references/UPSTREAM.md`，待补）。
- 远期规模目标与 30 Hz 帧率存在潜在冲突，提升规模前必须复核。
- JASS 一旦启动，需要单独的方法论（脚本 VM、原生函数支持矩阵），不能靠现有内核契约推导。

## 复核点

- 用户或贡献者要求自定义地图 / 战役支持；
- 规模目标提升至 20,000 单位或玩家数超过 10；
- `godot_warcraft3` 导出格式变化，或决定自研解析器；
- 决定引入战争迷雾、JASS 或跨版本存档（**「决定引入战争迷雾」一项已于 2026-11-14 触发并完成复核**，见下「修订记录」）。

## 修订记录

### 2026-11-14：战争迷雾 / 隐身纳入 1.0（用户拍板）

- **触发**：上述复核点「决定引入战争迷雾」。用户 2026-11-14 拍板把战争迷雾 / 隐身纳入项目 1.0 范围；1.0 业务规则单一权威为 `docs/references/WC3-MELEE-RULES.md` §0（S3「4 种族功能做完」需暗夜夜间隐身 / 昼夜 R10 / R2，§0.3 T2）。
- **决议**：上节「明确不做」中「战争迷雾 / 隐身反隐体系：后续单独机制，不挤进第一版」一条自本修订起被 supersede，改为**纳入 1.0**；其余「明确不做」条目（JASS / wtg VM、自定义地图、战役、Mod API、官方战网、Godot 宿主等）**不变**。原文保留不删，以存决策历史。
- **约束（承 §决策 / ADR 0002）**：迷雾 / 视野 MUST 为**表现层只读派生**，MUST NOT 进入权威状态 / 状态哈希 / 快照；`w3-core` 零改动、不新增权威状态字段、`SNAPSHOT_VERSION`（当前 3）不变。这与 P8 路线图 `docs/roadmap/P8-human-orc-melee.md` P8.5e「迷雾 MUST NOT 进权威状态 / 哈希 / 快照」一致。
- **范围澄清（同日，一并记录）**：用户再澄清 1.0「局域网联机对战」含「真人 VS AI 敌人玩家」，AI 玩家全部功能属 1.0 必做，「不做单机对战」收敛为仅不做纯本地单机对局形态；`openspec/config.yaml` 的「第一版范围之外」清单相应移除迷雾 / 隐身。1.0 范围口径以 `WC3-MELEE-RULES.md` §0 为准，本 ADR 只记「为什么决定」。
- **未变**：30 Hz 整数帧、10 名玩家 / 300 活跃单位验证规模、零资产边界、自建 lobby / relay、其余复核点均沿用原决策。

### 2026-11-25：明确长期目标为像素级复刻 War3，1.0 为短期目标（用户拍板）

- **触发**：用户 2026-11-25 明确拍板：本项目最终目标是「像素级复刻 War3」，1.0（局域网联机 Melee 对战）只是短期目标。此前「是否引入 REA / 反编译工作流验证 War3」讨论的结论为不引入，四条理由之一是「目标错配」（认为 1.0 是功能正确性目标、不是像素对齐）；用户以该长期目标质疑此条。重估结论：「目标错配」一条在**长期呈现层对齐**口径下**不再成立，应予撤回**——反编译 / 抓帧对齐的水面绘制顺序、透明排序、遮挡剔除、粒子、动画混合、原版 UI 观感，确实与「像素级复刻」对位。但「不引入反编译 / REA 整套工作流」的**结论整体不翻盘**，理由改由**当前阶段 + 合规姿态 + 可复现门禁 + 已有更高信噪比的替代路径**支撑，不再以「最终目标不是像素级」为依据。
- **决议**：
  - 「目标」与分期表的 **1.0 范围不变**：第一版仍为确定性模拟内核 + 命令帧同步联机 + Melee 对战（含真人 VS AI 玩家、回放、四族、道具、野怪、中立建筑、战争迷雾 / 隐身），业务规则单一权威仍为 `docs/references/WC3-MELEE-RULES.md` §0。
  - **新增长期方向**：项目最终目标为「像素级复刻 War3」，含呈现层像素对齐（绘制顺序、透明排序、遮挡剔除、粒子、动画混合、原版 UI 观感）；1.0 是达成该目标前的短期里程碑，不是目标上限。
  - 「明确不做（第一版）」与「合规」两节既有条目**全部不变**：JASS / 触发器 VM、自定义地图、战役、官方战网、任何暴雪资产的提交或分发仍不做；MPQ 及其派生文件仍一律不入库，运行时按 `config.toml` 本机路径读取。
- **红线不变（承 ADR 0001 / ADR 0002）**：
  - 长期目标属呈现层对齐，MUST NOT 解释为放宽 [ADR 0001](0001-license.md) 合规边界：工具合规 ≠ 用法合规 ≠ 产物可入库；反编译 / 抓帧若将来引入，产物 MUST 为只读 / 离线 / 本机 / 不入库，且不得进入任何仓库 artifact。
  - [ADR 0002](0002-determinism.md) 确定性门禁不变：表现层仍为只读派生，不得进入权威状态 / 状态哈希 / 快照；`SNAPSHOT_VERSION` / `SIM_VERSION` / `PROTOCOL_VERSION` 不因本修订 bump；状态哈希、golden hash、determinism 验收口径不变。反编译产出的是「视觉 oracle」，不是 ADR 0002 要求的「可冻结、机器可判、可进 CI 的业务逻辑 oracle」，只能用于离屏 / 人眼对照。
- **呈现层对齐的既定路径（本修订不新增工具链）**：本机正版客户端导出资产（`godot_warcraft3` 管线，见分期表 P3）+ `crates/w3-render` 离屏 `render_headless_rgba` / `render_headless_rgba_with_textures` 像素对照 + 真窗口人工验收 + 五个只读参考项目。反编译 / REA 整套工作流**截至本修订仍未引入**；若将来确需，须先按本 ADR 复核点单独立项、走规格门并由人拍板试点边界。
- **复核点补充**：「决定引入反编译 / 抓帧 / REA 类逆向流程」或「决定把像素级复刻拆分为独立阶段 ADR」时，须重新评估本 ADR 与 ADR 0001 / ADR 0002 的边界；本条仅记于本节，不改动正文「## 复核点」清单。
- **流程说明**：本修订属纯文档 / 规则改动、目标与方向已清楚，按 `CODEBUDDY.md` §9「目标与方向已清楚的小改动、纯文档 / 规则改动可显式声明省略规格门」显式声明省略 OpenSpec 规格门，不新建 change、不成文四件套。
- **未变**：30 Hz 整数帧、10 名玩家 / 300 活跃单位验证规模、零资产边界、自建 lobby / relay、P0–P6 分期状态、其余复核点。

### 2026-11-25（第二次修订）：引入 clean-room 反编译证据流程试点（用户拍板）

- **触发**：用户 2026-11-25 明确「已决定本项目引入反编译 War3 的工作流」，并选择「ADR 修订 + 形态 A 试点」。同日第一次修订（见上一小节）明文写「反编译 / REA 整套工作流截至本修订仍未引入」，本次拍板推翻该状态；按「由人拍板的修订记录承接」，以本小节承接状态翻转，第一次修订原文一字不改、不静默改写。
- **决议**：
  - 新增「呈现层证据流程」作为长期目标（像素级复刻 War3）的承接手段：以 clean-room 方式从 WC3 原生二进制取得**行为规格**（绘制顺序、透明排序、遮挡剔除、粒子、动画播放混合、UI 观感等呈现层行为），用于呈现层像素对齐；明确这是**视觉 oracle / 行为规格**，不是可编译进项目的代码，也不是 [ADR 0002](0002-determinism.md) 口径的业务逻辑 oracle。
  - 形态 A 试点：`craft-anything`（MIT OR Apache-2.0）作为**本机外部工具**（CLI / MCP）运行，不入库 / 不复制代码 / 不作为 crate 依赖 / 不登记 `NOTICE.md`；反编译产物（伪 C、调用图、行为规格、证据记录）存**仓库外本机证据目录**，生产侧与消费侧只通过主仓库只读文档交接。
  - 消费侧沿用既有呈现层路径：`crates/w3-render` 离屏 `render_headless_rgba` / `render_headless_rgba_with_textures` + ViewImage + 真窗口人工验收作视觉 oracle。该外部工具无 MPQ / BLP / MDX / SLK 专用解析器，WC3 资产与数据表仍以 `godot_warcraft3` 导出管线为准。
  - 试点先限**单个呈现特性**，具体特性选择由后续试点 change 的规格门拍板；按「工作流改进先试点再固化」，验证闭环后再决定是否推广，本修订不固化任何模板 / 规则。
- **红线不变（承 ADR 0001 / ADR 0002）**：
  - [ADR 0001](0001-license.md)：零资产入库、MPQ 及其派生文件不入库、不复制上游代码、不绕过 EULA / DRM / 登录 / 反作弊；仅用于用户合法自备的经典客户端，`README.md` 免责声明继续有效。反编译产物一律「只读 / 离线 / 本机 / 不入库 / 不随发行物分发」。
  - [ADR 0002](0002-determinism.md)：反编译证据 MUST NOT 进入权威状态 / 状态哈希 / 快照 / golden hash / determinism 验收 / CI 门禁；不因本修订 bump `SNAPSHOT_VERSION` / `SIM_VERSION` / `PROTOCOL_VERSION`；`w3-core` 零改动；表现层仍为只读派生。
