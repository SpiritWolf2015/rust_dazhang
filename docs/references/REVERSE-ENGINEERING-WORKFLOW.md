## 1. 取证流程的通用工程环节

> **来源定性（本节通用）**：本节只描述 clean-room 取证流程的一般工程环节，是本项目自定的流程说明，不引用任何外部资料、不附带外部资料行号，也不是 WC3 玩法 / 格式 / 数值事实来源。

### 1.1 触发与目标收敛

- **触发**：呈现层表现或业务行为无法靠推测对齐，需要一个可验证的事实依据。
- **角色**：消费侧（实现方）。
- **动作**：把待确认的问题收敛为单个可验证目标，登记为需求 claim。
- **产物与去向**：目标 claim 进入取证队列；本仓库承接为 [ADR 0003](../decisions/0003-scope.md) 第二次修订的长期目标。

### 1.2 生产侧 / 消费侧分离与文档交接

- **触发**：取证长程任务与实现互不干扰，且不想膨胀仓库。
- **角色**：生产侧（取证方）与消费侧（实现方）分离；两侧只通过只读文档交接，不共享代码、不共享运行时。
- **动作**：另起仓库外证据目录；生产侧只写证据与行为规格，消费侧只读文档。
- **产物与去向**：证据记录 / 行为规格经文档交接到消费侧。

### 1.3 长程任务分类

- **触发**：单轮会话撑不住持续数小时 / 数天的长程工作，需要可续跑的任务分类。
- **动作**：把长程工作拆为「探索与证据积累 / 目标实现与缺失补全 / 工程整理 / 自动化验证与反馈」几类可续跑任务。
- **产物与去向**：各类产出统一汇入证据目录与任务队列。

### 1.4 并行与调度

- **触发**：取证与重建天然可并行，串行浪费时间。
- **动作**：主会话派发、子任务并行、设熔断、错误报告自动生成任务回灌队列。
- **产物与去向**：并行产出的证据节点与自动生成的返工任务，回到证据目录与任务队列。

### 1.5 证据结构化与独立重审

- **触发**：产出方自审不足以证明结论为真，需交叉核验。
- **动作**：每条判定与其依据产物同批留存，并经独立重审；判定与产物同提交、不由产出方自审通过。
- **产物与去向**：带产物的判定与独立重审记录写入证据目录。

### 1.6 工程护栏

- **触发**：长程会话漂移、仓库膨胀、临时约束被当永久规则。
- **动作**：约束会话的边界与范围、给临时约束标注时间与作用域、控制代码膨胀、必要时重写而非局部修补。
- **产物与去向**：护栏约定留在各自规范文件，不进本仓库权威状态 / 门禁。

> **本节结论（产出定性）**：取证产出的是**行为规格 / 证据节点，不是代码**；本节只作流程说明，不复制任何外部实现、不引入外部技术栈、不作 WC3 玩法 / 格式 / 数值事实来源、不登记为第六个只读参考项目。

## 5. 两条反馈循环

两条回路严格区分，MUST NOT 混为一谈，且 Check 不达标一律不标通过：

- **回路一：探索 ↔ 实现**（`Study` ↔ `Build` 之间反复）。取证得到的证据不足 / 假设被推翻时，回到 `Deep 取证` 补证据；`Build` 重建中发现缺失也回探索。角色是生产侧探索会话 + 消费侧实现会话，靠只读文档交接，不共享运行时。
- **回路二：Check → 新抓取需求**（不达标回炉）。Check 判据不达标时，**不达标转新抓取需求**（一律不作通过结论），用 `README.md:222` 的 `--continue-in` / `--rounds` 续跑参数回到取证步重新取证据；产物为新抓取需求 + 新一轮 `ev_` claim，落点在仓库外证据目录。

> 工具入口：`--continue-in` / `--rounds`（`README.md:222`，本机外部工具行号 / 仓库外证据 / 人工确认项 / 可能漂移）；探索 与 实现、Check 与 新抓取需求 分属两条回路，收敛结论由人拍板、不拿沉默当授权。
