> 每个决策统一列出：决策 / 备选方案（含否决理由）/ **ADR 0002 关联与对跨平台确定性的影响** / 架构原则对照 / 业务规则编号与核实状态（`[已核]` / `[待核]` / `[取舍]`）。跨平台确定性现状：仅 Windows 11 与 Debian 12 x86_64 / rustc 1.99.1 经离线 golden hash 逐字节比对验证（ADR 0002 复核记录 / 主 `cross-platform-determinism/spec.md`）；macOS / ARM64 / 其它 rustc 仍待验证，**本 change 不得声称有新验证或全平台达成**。

### D1：选族入口 = 表现层本地只读状态 → 装配期传参 `MeleeSetup::with_races`（Q1 已拍板）

- **决策**：在 HUD / 输入层提供开局前本地族 / AI 族选择（**Q1 用户 2026-11-18 拍板：窗口内 egui overlay**），选族状态只停 `w3-client` 表现层；确认后把 `(local_race, ai_race)` 作为参数传给既有 `MeleeSetup::with_races(local_race, ai_race)` 再装配 `ClientApp`。`Race` 只用于选 DefId 段，MUST NOT 写入 `w3-core` 的 `Player` / `RtsMatch`。未选族回落 `MeleeSetup::new()`（本地人族 / AI 兽族）。
- **备选方案**：① 在 `w3-core` 加 `Player.race` / `RtsMatch.race` 权威字段承载选族 → **否决**：新增权威状态须同步进状态哈希 / 快照 / `first_difference()`、可能升 `SNAPSHOT_VERSION`，违反 C1 / ADR 0002 §6-8 与主 `dual-faction/spec.md:25`；② 给 `CommandKind::Spawn` 加 `DefId` 字段 → **否决**：改 `w3-core` 命令线格式，`Spawn` 字节不再逐字节一致；③ 命令行参数 + HUD 只读标签（Q1 备选①）→ **本次用户未选**（按推荐选窗口内 overlay），非否决但不在本期；④ 独立开局前菜单窗口（Q1 备选②）→ **否决**：引入新窗口 / 事件循环形态，违反主 `playable-window-entry/spec.md:10/:24` 单一入口契约；⑤ 复用 1.0 联机选族流程（Q1 备选③）→ **否决**：T5 未定、联机底座本期不重做（用户 P1 被否备选 D）。
- **ADR 0002 关联与跨平台确定性影响**：零影响。`w3-core` 零 diff、无新增权威状态 / 命令 / 事件，30 Hz 整数帧、命令稳定排序键、稳定 `EntityId` 顺序、FNV-1a 哈希字段集合、`SNAPSHOT_VERSION`（3）、golden hash 逐字节不变；选族是装配期只读参数，不同平台相同参数产生相同 `Spawn` 字节，不引入平台相关输入。本 change 不新增 `defs_hash` / `content_hash` 变化（`crates/w3-client/examples/melee.rs:38` 固定 `CONTENT_HASH`）。
- **架构原则**：DIP、SRP、唯一状态所有者（内核仍是唯一写入者）。
- **规则编号与核实状态**：§0 S1 / S3 `[已核]`（1.0 范围用户拍板）、R2 `[已核]` + `[取舍]`（合成原创分段常量）、R12.7 `[取舍]`、Q1 `[已核]`（2026-11-18 用户拍板）。
