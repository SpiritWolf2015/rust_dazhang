# Proposal

## Why

落实路线图 `docs/roadmap/P8-human-orc-melee.md §3 P8.5`（:119-131）的 **P8.5c「野怪营地与掉落」**：`:127` 表行「中立野怪 AI（leash / 归巢）、死亡掉落表、确定性随机码」，验收「**清野可重复、掉落逐帧一致**」；P8.5 全量已由用户 2026-11-14 拍板必做（:28 / :151），五个子系统各单独 change、串行推进、不塞回 P8.0–P8.4（:121 / :30），P8.5a `p8-hero-revive`、P8.5b `p8-townhall-upgrade` 均已归档、本 change 紧接。本轮授权口径为「直到规格门再请你拍板」——**方向 A / B / A′ 尚未拍板**，`reference-researcher` 只读对照报告给出单一推荐 **A（按 ADR 0002 全流程改 `w3-core`、新增权威状态进 FNV-1a 状态哈希 / 快照 / `first_difference()`）**，四件套按推荐 A 收敛为**单一口径**写成提案（`decision-memo.md` 的 P1 明确记为「推荐 A，待规格门 Q1 由用户拍板」，**不写成「用户已确认 / 已拍板」**），规格门定案；B「表现层只读派生、内核零改动」与 A′「混合」判为「降级验收、MUST NOT 静默采用」并登记被否方向台账。现状内核无野怪 / 营地 / 中立归属、无掉落表 / 地面物品 / `ItemInstance`、无击杀收益结算、无确定性掉落随机码消费（详见 `decision-memo.md` C6–C11 与 `design.md` Context 现状差距 8 项），路线图 `:131` 硬约束要求「掉落随机码若需进权威状态 MUST 按第 4 节走 ADR 0002 流程，否则一律表现层只读派生」。业务规则依据 `docs/references/WC3-MELEE-RULES.md` 正文**当前行号**：**R8.1–R8.6**（野怪定义 / 分级 / 击杀收益 / 昼夜 / leash「MUST NOT 无限追出营地」:192 / **R8.6「掉落 MUST 由冻结随机码（种子随对局快照）决定，重放一致」:194 `[取舍]`**，正文 :186-196）、**R1.1**（地面物品＝野怪掉落宝物无主，:72）、**R1.4**（框选命令过滤，:96-101）、**R6.1**（等级经验，:165）/ **R6.2**（物品栏，:166）、**R7.1**（道具分类，:177）/ **R7.2**（来源，:178）/ **R7.5**（实例独立，:181）/ **R7.6**（走 `EffectDef` 不做 JASS VM，:182）、**R9.1–R9.3**（中立建筑，:214-216）、**R11**（胜负，:231-237）、**R12**（AI 玩家 / 回放，:241-249）、**R13**（操作层，:253-324）、**§14**（与本机导出不符标 `[待核]` 并回到人拍板、不静默改规则，:392-397）；附录 `:352-369` 佐证表内的 `R8.5 :184` / `R6.5 :163` / `R9.1 :205` 是 2026-11-15 增补 §13 之前的**历史旧行号，本 change 不沿用**。1.0 范围 **S1**（局域网联机对战，含真人 VS AI 敌人玩家）/ **S2**（回放录像）/ **S3**（四族功能做完）/ **S4**（各种道具）/ **S5**（地图上的野怪）/ **S6**（中立建筑功能）见 §0（:17-49）；不做范围 **N1–N6** 不纳入。相关 ADR：**0001**（零资产 / 许可证）、**0002**（确定性硬门禁）、**0003**（范围与分期）、**0004**（冻结坐标）、**0005**（联机线格式与 protobuf 分层边界）。

## What Changes

- **推荐方向 A：新增确定性权威状态并纳入 ADR 0002 全流程**（待规格门 Q1 拍板）。在 `w3-core` 新增野怪 / 营地 / leash / home 状态、掉落表冻结常量、击杀收益结算、地面物品 / 物品实例、确定性随机码消费序列等权威状态，全部 MUST 同步进入 FNV-1a 状态哈希、由 `SNAPSHOT_VERSION` 定义的快照与 `first_difference()`（当前 5，按 Q4 推荐 bump 5→6）。30 Hz 整数帧、`ExecuteFrame → PlayerId → Sequence → Arrival` 稳定排序键、稳定 `EntityId` 顺序不变；野怪实体 / 营地归属与「无主地面物品」（R8.1 / R1.1）的建模属 Q7 待拍板项，不预设结论。
- **野怪 AI 复用既有命令面**：leash / 归巢按 `IDLE / ENGAGED / RETURNING` 状态机 + home 锚点 + 定义层 `acquisitionRange` 驱动，MUST NOT 无限追出营地（R8.5）；复用既有 `Attack` / `Move` 命令面与 `run_ai` 确定性重算框架，**不新设 AI × lockstep 架构**（`WC3-MELEE-RULES.md` §0.3 T5 / :57 留后续）。
- **确定性随机码消费契约**（Q6 待拍板，推荐）：复用现有 match-owned 整数 LCG + `seed` 随快照，掉落按死亡事件以稳定 `EntityId` 顺序确定性消费、消费序列进状态哈希 / 快照；MUST NOT 用 Godot `RandomNumberGenerator` / `randomize()` / 墙钟 / `HashMap` 迭代顺序（参考对照报告结论 5 的「明确不借鉴」）。
- **击杀收益与掉落**：击杀野怪 MUST 结算经验（R6.1）/ 金币（R8.3）/ 掉落（R7.2）；掉落表为「表 → 互斥 set → 概率条目」分层的合成 / 原创编译期整数常量 `[待核]`，死亡事件幂等、同 seed 可复现（R8.6 / R7.5）；地面物品（或掉落事实）作为权威状态进哈希 / 快照；拾取 / 六格背包 / 商店购买 / 回城卷轴全部留 **P8.5d**（`:128`，Q2 推荐范围）。
- **BREAKING（按 Q4 / Q5 推荐，待规格门拍板）**：`SNAPSHOT_VERSION` / `SIM_VERSION` **5→6**（连同快照头部、单测硬断言、golden hash 基线、主 specs 口径、ADR 0002 复核记录追加；旧 v5 快照 / 回放按 `UnsupportedVersion` / `SimVersionMismatch` 明确拒绝、不提供跨版本迁移）；golden hash 按新实现重取、必变、不沿用 P8.5b v5 值；若新增 `GameplayCommandKind` / `EventKind` 变体，proto 只追加 tag（现 `reserved 14 to 32`、已用 33/34/35，新增从 **36** 起）、`PROTOCOL_VERSION` 5→6、`Packet::decode` 对旧版本 `VersionMismatch` 明确拒绝、`w3-render/src/scene.rs` 补穷尽分支、`net-owner` / `client-owner` 串行协作、relay 双客户端确定性。字段编号只追加、删除保留 `reserved`、canonical 约束（禁 `map` / 禁 `float`）继续适用。
- **主 specs 口径同步修订（B-1 教训）**：用 `## MODIFIED Requirements` delta 覆盖 `faction-definitions` / `melee-match` / `human-faction` / `orc-faction` / `gameplay-systems` / `command-hotkeys` 这 6 个承重 capability 中「P8.5b bump 4→5 / tier 顶层权威状态 / `UpgradeTownHall` 码 13 / tag 35」等历史口径为本 change 的「bump 5→6 / 野怪营地与掉落权威状态 / 确定性随机码消费序列」口径，逐字保留全部历史 `#### Scenario:` 标题作身份键、口径写进 requirement 新正文与 THEN、MUST NOT 写 `## Purpose` 覆盖 delta；归档时才合并，本阶段不改主 `openspec/specs/**` 正文。其余含同类历史口径的主 specs 是否本 change 全量修订属 **Q10 待拍板项、不预设结论**（推荐沿 P8.5a / P8.5b 先例登记为已知限制、由 `docs-owner` 后续独立 change 统一收口）。
- **回归与门禁**：`cargo test -p w3-core --test determinism`（26 项）+「改坏验红」按 `CODEBUDDY.md §5` 形态①（测试内构造反例 + 元断言防退化，Q9 推荐），覆盖 tier / rng / 掉落 / 收益 / 哈希漏接等退化；`cargo test --workspace` / `cargo fmt --all -- --check` / `check_encoding.py` / `verify_all.py`（规格门 `status: pending` 期 fail-closed 为正确信号，不绕过、不改门禁）；真窗口人工清单保持 `- [ ]`「未执行 / 待人工」。
- **表现层只读派生**：HUD 只读派生、表现层不得反写权威状态 / 不进哈希 / 快照 / `first_difference()`（ADR 0002 §5）；`w3-core` 仍不得依赖 `w3-content` / render / ui / audio / net。
