# Proposal

## Why

落实路线图 `docs/roadmap/P8-human-orc-melee.md:128` 的 **P8.5d「物品 / 商店 / 回城卷轴」**，验收「拾取 / 购买 / 使用闭环，实例不共用充能」；P8.5 全量由用户 2026-11-14 拍板必做、五子系统串行（`:121` / `:151`），P8.5a / b / c 已归档。主 `openspec/specs/creep-camps/spec.md:80,164` 与 `crates/w3-core/src/creep.rs:331` 明文把「拾取 / 六格背包 / 商店购买 / 回城卷轴」留 P8.5d，构成本期承重边界。内核现状不足以闭环：`BuyItem` 仍是 P5 占位（`sim_match.rs:1263-1272` 只 `bag.push`、不扣 gold / 不校验 / 不建实例 / 不进六格背包）、`bag: Vec<DefId>` 无界非实例（`gameplay.rs:1091`）、`HeroState` 无 inventory（`gameplay.rs:875`）、无 shop 段、client 无商店 DefId。验收线 R7.5（`:181`）「实例独立充能」必然要求改 `w3-core` 新增权威状态 → `reference-researcher` 只读对照报告给出单一推荐 **A（按 ADR 0002 全流程改内核真闭环）**；B「表现层假闭环」/ A′「混合」判降级验收、MUST NOT 静默采用。规则依据 `WC3-MELEE-RULES.md` R6.2 / R6.3、R7.1–R7.6、R8.3 / R8.6、R9.1 / R9.3、R1.1 / R1.4 / R13.6、R12.2 / R12.4、R13.5、§0 S4 / S6、§14（`:394`）；ADR 0001–0005。**方向 A / B / A′ 与 Q1–Q12 尚未拍板**，本轮授权「直到规格门再请你拍板」，不拿沉默当授权。

## What Changes

- **推荐方向 A：新增确定性权威状态并纳入 ADR 0002 全流程**（待规格门 Q1 拍板）。在 `w3-core` 新增英雄六格背包（每格挂物品实例，R6.2）、拾取 / 购买 / 使用 / 丢弃 / 移交 / 售卖 / 商店库存与刷新 / 回城卷轴传送（施法帧、目标、中断）等权威状态，全部 MUST 同步进入 FNV-1a 状态哈希、由 `SNAPSHOT_VERSION` 定义的快照与 `first_difference()`（当前 6，按 Q4 推荐 bump 6→7）。30 Hz 整数帧、`ExecuteFrame → PlayerId → Sequence → Arrival` 稳定排序键、稳定 `EntityId` 顺序不变；实例独立充能 / 冷却 MUST 挂实例而非 `ItemDef`（R7.5），「实例不共用充能」是本期验收主体。HUD 只读派生、表现层不得反写权威状态。
- **P8.5c→P8.5d 承重衔接**：地面物品 → 拾取 → 六格背包 → 使用 → 丢弃 / 售卖 → 商店库存刷新 → 回城传送的完整状态迁移链，MUST 复用 P8.5c `ground_items` / `item_instances` / `neutral` 权威字段（`creep.rs:394-419`）与 `ItemInstanceState { item_def, charges, cooldown_frames, effect }`（`creep.rs:333-338`），扩展出 owner / 槽位而保持实例身份；`complete_revive()`（`sim_match.rs:1526-1558`）逐项恢复 `bag` 的既有语义 MUST 同步为「六格实例背包按实例身份恢复」（R6.3）。背包建模（扩展 `ItemInstanceState` vs 新建持有实例容器、与 `bag: Vec<DefId>` 收敛）属 Q7 待拍板项，不预设结论。
- **购买 / 售卖 / 黄金结算走既有事务命令面**：商店购买 MUST 为「距离 / 库存 / 黄金校验 → 扣费 → 入包 → 库存递减 → 满包或资源不足回滚退款」事务（R7.3 / R9.3），复用既有事务先例（复活 / 主城升级的 `submit_*` / `refund_*`）；售卖回购价 `[待核]`（R7.4），黄金结算 MUST 经既有命令面与资源结算、不新增旁路写入（R9.3 / R13.6）。道具效果 MUST 走既有 `EffectDef` 组合、不执行 JASS（R7.6）。地面物品 / 商店（中立建筑）无主、不可移动，MUST NOT 出现在 `Move` 命令生成集合（R1.1 / R1.4）；新增命令变体 MUST NOT 借只读视图投影放松旁路门禁（R13.6 `:314`）。
- **确定性随机码 / 市场刷新**：市场刷新与掉落后续消费 MUST 复用 P8.5c match-owned 整数 LCG + `seed` 随快照、`rng_state` / `rng_draws` / `next_rng_seq` 事件驱动流 + 显式消费序列契约（R8.6），消费序列进状态哈希 / 快照 / `first_difference()`；MUST NOT 用墙钟 / `f64` / 表现层独立随机源 / `HashMap` 迭代顺序。是否复用同一流、具体消费序列编码属 Q6 待拍板项。
- **回城卷轴**：MUST 有独立命令 / 事件语义，目标按「友方主城分类」数据驱动、无可用友方主城显式拒单、施法帧 / 次数 / 中断作独立权威状态，与大法师 MassTeleport 明确区分（参考对照结论 7）；`Event` 无 payload 下按 `Event.entity` 查表表达事实（照 P8.5c D6）。传送目标语义、`Event` 表达、是否新增命令变体属 Q5 / Q6 待拍板项。
- **BREAKING（按 Q4 / Q5 推荐，待规格门拍板）**：`SNAPSHOT_VERSION` / `SIM_VERSION` **6→7**（连同快照头部、单测硬断言、golden hash 基线、主 specs 口径、ADR 0002 复核记录追加；旧 v6 快照 / 回放按 `UnsupportedVersion` / `SimVersionMismatch` 明确拒绝、不提供跨版本迁移）；golden hash 按新实现重取、必变、不沿用 P8.5c v6 值 `0xc802b63cd6c55b74`；若新增 `GameplayCommandKind` / `EventKind` 变体，proto 只追加 tag（现 `reserved 14 to 32`、已用 33/34/35/36，新增从 **37** 起）、`PROTOCOL_VERSION` 6→7、`Packet::decode` 对旧版本 `VersionMismatch` 明确拒绝、`w3-render/src/scene.rs` 补穷尽分支、`net-owner` / `client-owner` 串行协作、relay 双客户端确定性；payload 14→N 双向穷尽映射、canonical 约束（禁 `map` / 禁 `float`）继续适用。
- **主 specs 口径同步修订（B-1 教训）**：用 `## MODIFIED Requirements` delta 覆盖 `faction-definitions` / `melee-match` / `human-faction` / `orc-faction` / `gameplay-systems` / `command-hotkeys` 这 6 个承重 capability 中「P8.5c bump 5→6 / 野怪营地与掉落权威状态 / tag 36 / `PROTOCOL_VERSION` 5→6」历史口径为本 change 的「bump 6→7 / 物品商店回城权威状态 / tag 37 / 6→7」口径，逐字保留全部历史 `#### Scenario:` 标题作身份键、口径写进 requirement 新正文与 THEN、MUST NOT 写 `## Purpose` 覆盖 delta；归档时才合并，本阶段不改主 `openspec/specs/**` 正文。其余含同类历史口径的主 specs（含 `creep-camps` 明文交接措辞 / `hero-revive` / `town-hall-upgrade` 等）是否本 change 全量修订属 **Q10 待拍板项、不预设结论**（推荐沿 P8.5a / P8.5b / P8.5c 先例登记为已知限制、由 `docs-owner` 后续独立 change 统一收口）。
- **回归与门禁**：`cargo test -p w3-core --test determinism`（26 项）+「改坏验红」按 `CODEBUDDY.md §5` 形态①（测试内构造反例 + 元断言防退化，Q9 推荐），覆盖六格背包 / 实例充能冷却 / 购买事务 / 哈希漏接等退化；`cargo test --workspace` / `cargo fmt --all -- --check` / `check_encoding.py` / `verify_all.py`（规格门 `status: pending` 期 fail-closed 为正确信号，不绕过、不改门禁）；真窗口人工清单保持 `- [ ]`「未执行 / 待人工」。
- **表现层只读派生**：六格背包 / 商店命令卡 / 购买 / 拾取 / 回城进度 HUD 只读派生、表现层不得反写权威状态 / 不进哈希 / 快照 / `first_difference()`（ADR 0002 §5 / R10.5 / R13.5）；`w3-core` 仍不得依赖 `w3-content` / render / ui / audio / net。
