# ADR 0001：采用 GPLv3 作为项目许可证

- **状态**：Accepted
- **日期**：2026-11-07
- **决策者**：项目发起阶段
- **相关**：许可证选择、上游代码复用、商业化约束

## 背景（Context）

新项目 `rust_dazhang` 从零用 Rust 编写，**不复制任何上游仓库的代码**，只借鉴设计与格式规格。三个参考项目的许可证：

| 上游 | 许可证 | 备注 |
|---|---|---|
| `vera20k` | GPLv3 + Section 7 附加条款 | `README.md:142`、`LICENSE-GPL` 为 v3 全文，无 "or later"；附加条款见 `LEGAL.md` |
| `godot_warcraft3` | MIT | |
| `rts_kernel_cs` | MIT | |

发起人的核心诉求是：**防止他人把本项目成果做成闭源商业产品**。同时希望许可证尽量简单、不要自定义条款，并在将来有条件地允许与 `vera20k` 交换代码。

需要一并澄清的边界：许可证只覆盖**代码**；暴雪的 MPQ 资产、商标、游戏内专名不受本项目许可证约束，也不因开源而变得可分发。

## 决策（Decision）

采用**标准 GPLv3-only**（仓库根目录 `LICENSE` 即为 GPLv3 全文），**不附加任何 Section 7 自定义条款**。

配套约定：

1. `CONTRIBUTING.md` 写明贡献代码按 GPLv3 授权；如未来考虑双许可商业化，需提前引入 DCO/CLA，否则接受外部贡献后难以变更许可证。
2. 不复制 `vera20k` 的 `LEGAL.md` 附加条款。只有**真的引入其代码**时，那些条款（改名、不得冒充官方、不给官方 lobby/relay 访问权）才随之进入；纯自写代码不受影响。
3. 商标与资产合规独立于许可证：`README.md` 的免责声明、`.gitignore` 的资产排除规则、`config.toml.example` 的本机路径模型共同构成合规边界。

## 备选方案（Alternatives considered）

| 方案 | 结论 | 理由 |
|---|---|---|
| **MIT / Apache-2.0** | 否决 | 允许他人闭源再分发并商业化，与发起人诉求直接冲突。 |
| **GPLv2** | 否决 | 与 GPLv3 **不兼容**（`vera20k` 为 GPLv3-only），未来无法与其交换代码；且 2026 年的新项目选 v2 无收益（缺专利授权与反硬件锁条款）。 |
| **AGPLv3** | 备选，暂不采用 | 唯一能覆盖"纯网络服务 / SaaS / 云游戏不分发二进制"的漏洞。代价是生态更窄、劝退部分贡献者与集成方。若将来主力形态变成托管联机服务且出现该风险，再评估迁移。 |
| **双许可（GPLv3 + 商业）** | 暂不采用 | 需要 CLA/DCO 与版权集中，P0 阶段过度设计；保留为未来选项。 |
| **GPLv3 + 自定义附加条款** | 否决 | 自定义条款降低与其他 GPL 项目的互操作性，且本项目不需要靠它保护商标（商标权与名称合规是独立问题）。 |

## 后果（Consequences）

**正面**

- 阻止分发闭源修改版、阻止把代码并入专有产品、阻止用 DRM/硬件锁限制用户运行修改版。
- 与 `vera20k` 同协议，将来可合法借用其 `net/` / `services/relay-protocol` 代码。
- MIT 上游与 GPLv3 单向兼容，借鉴或引入其代码片段无障碍（保留 MIT 版权声明）。
- 标准文本，GitHub / GitCode 等平台可直接识别，无自定义条款的解释成本。

**负面 / 需要明确接受**

- **不阻止收费销售、商业支持或提供服务**——GPLv3 禁止的是"闭源分发衍生作品"，不是商业化本身。
- **不覆盖 SaaS / 纯网络服务**：对手若不分发二进制而只提供在线服务，GPLv3 不触发源码义务（这是 AGPLv3 才解决的）。
- **不阻止私有修改自用**，也不阻止他人用原创资产另立品牌竞争。
- **copyleft 也约束发起人自己**：接受外部贡献后，改许可证或做商业双许可需逐个取得同意。
- 贡献者门槛高于 MIT/Apache；部分组织规避 GPL 依赖。

**不覆盖**

- 任何游戏资产、由资产派生的数据文件、商标、游戏内专有名称与美术。
- 他人合法取得的客户端与资产的所有权或使用权。

## 复核点

出现以下情况时重新评估本 ADR：

- 决定直接引入 `vera20k` 代码（需同时审查其 `LEGAL.md` 附加条款）；
- 项目形态转为以托管联机服务为主（评估 AGPLv3）；
- 计划商业双许可（需先落地 DCO/CLA）。
