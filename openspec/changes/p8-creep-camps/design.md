## Decisions

> 每个决策统一列出：决策 / 备选方案（含否决理由）/ **ADR 0002 关联与对跨平台确定性的影响** / 架构原则对照 / 业务规则编号与核实状态（`[已核]` / `[待核]` / `[取舍]`）。**Q1–Q12 按「推荐」收敛为 P1=A 单一口径一次成文**（不写「可容纳两种结果」、不列两分支 tasks），但推荐值本身**尚未获规格门拍板**（`decision-memo.md`「## 待确认项」保留逐条「推荐 + 依据 + 代价 + 备选」原文、规格门 `status: pending`）；若规格门拍板结果与推荐不同，MUST 按 `CODEBUDDY.md §8` 同步回查四件套、由 `spec-steward` 修订后重走规格门。跨平台确定性现状：仅 Windows 11 与 Debian 12 x86_64 / rustc 1.99.1（v3）经离线 golden hash 逐字节比对验证（`ADR 0002` 复核记录 / 主 `cross-platform-determinism/spec.md`）；**v4 / v5 / v6 的 Debian 侧比对仍待人工 / VM**，macOS / ARM64 / 其它 rustc 仍待验证，**本 change 不得声称有新验证或全平台达成**。

### D1：方向 A — 按 ADR 0002 全流程改 `w3-core` 新增权威状态（承重决策，推荐、待规格门 Q1 拍板）

### 第四节：核心架构问题（结论 7）—「清野可重复、掉落逐帧一致」+ R8.6 必然要求改 `w3-core` 并新增权威状态

- **锚**：`docs/roadmap/P8-human-orc-melee.md:127,131,135-141,146-152`（验收线 / §131 硬约束）；`docs/references/WC3-MELEE-RULES.md:72,96-101,165-166,177-182,188-194,214-216,233-249`（R1.1 / R1.4 / R6.1 / R6.2 / R7.1 / R7.2 / R7.5 / R7.6 / R8.1–R8.6 / R9.1–R9.3 / R11 / R12）；`docs/decisions/0002-determinism.md:44-60`（§4 随机流 / §5 状态权威与表现边界 / §6 状态哈希 / §7 快照）。
- **机制论证**：① 验收主体是**权威状态哈希逐帧一致**（`compute_state_hash` + determinism 26 项 + golden hash），不是画面；「掉落逐帧一致」若只在表现层用本地随机源画出来，哈希里根本没有掉落字段，无法被 `first_difference()` / 快照回放检出，且 ADR 0002 §4 要求「表现层未来须使用独立随机源」——两端独立随机源必然不等。② 「种子随对局快照」的底座已存在（`seed` / `rng` 进快照头，`sim_match.rs:2056,2061`），但当前是**每帧恰好消耗一次**（`:544-545`），掉落是**死亡事件驱动**抽取，必须设计「按稳定 `EntityId` 顺序消费随机流、消费序列进哈希 / 快照」——这本身是 `w3-core` 改动。③ 击杀收益（R8.3 经验给附近英雄、金币、掉落）落在 `HeroState.xp` / `PlayerEconomy.gold` / `bag`（`gameplay.rs:770,1042,984`）——全是已进哈希 / 快照的权威字段；表现层按 ADR 0002 §5「不得反写位置、朝向或生命」，更不得反写经济 / 经验 / 背包。④ `read_view()` / `drain_events()` 只给 owned 拷贝与事实事件，且 `Event` 无 payload、`EntityView` 无 `hero` / `xp` / `bag` / 地面物品（`sim_match.rs:187-216`）——表现层连「死的是哪个野怪、掉什么、给谁经验」都拿不到。⑤ R7.5 实例独立、R7.6 走 `EffectDef`、R9.3 走既有命令面与资源结算，都是权威结算，不是 HUD。
- **缺口具体在 6 个可观测行为**：(a) 野怪实体与中立归属不存在 → 清野无对象（R8.1 / R1.1）；(b) 无 home 锚点 / ENGAGED / RETURNING / `acquisitionRange` → R8.5「MUST NOT 无限追出营地」不可观测；(c) 死亡无经验 / 金币 / 掉落结算 → R6.1 / R8.3 不可观测，`xp` 从不增长；(d) 无掉落表 / 地面物品 / `ItemInstance` → R7.2 / R7.5 / R8.6 不可观测；(e) 无确定性随机码与掉落事实事件 → 「种子随快照」「重放一致」无法被哈希 / 快照验证；(f) 重开 / 回放一致性（R11.5 / R12.4）无法覆盖野怪与掉落。
- **对照 P8.5a / P8.5b 两次拍板**：P8.5a 归档 `openspec/changes/archive/2026-11-20-p8-hero-revive/decision-memo.md:44`（P1「改内核真复活（推荐）」）、`:45`（被否 B「只读派生降级」→「表现层 HUD 假复活、`w3-core` 零改动，需下调验收线…`reference-researcher` 判为『降级验收、MUST NOT 静默采用』」）、`:51`（R1 台账）；P8.5b 归档 `.../2026-11-20-p8-townhall-upgrade/decision-memo.md:42`（P1「方向 A 独立 tier 状态」）、`:44`（被否 B「表现层只读派生假升级」→「达不到验收线…P8.5a『假复活』已被否，属同一类降级方向」）、`:49`（R2）。两次均按 Q1 拍板 bump `SNAPSHOT_VERSION` 3→4→5、新增权威状态进哈希 / 快照 / `first_difference()`、determinism 26 项、golden hash 重取、ADR 0002 复核记录追加（`docs/decisions/0002-determinism.md:109-112`）。**本 change 的 B 方向与这两次被否方向同类**；差别只在 P8.5c 额外需要「确定性随机码消费契约」与「中立归属建模」，均无现成答案（见第七节）。
