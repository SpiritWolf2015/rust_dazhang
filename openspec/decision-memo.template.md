# 决策纪要模板

> 用法：制作 change 时在 `openspec/changes/<name>/decision-memo.md` 复制下方骨架并填写，与 `proposal.md` 同步产出。规则见 `CODEBUDDY.md` §8 与 `openspec/config.yaml` 的 `rules.proposal`；首个实例见 `openspec/changes/melee-playable-loop/decision-memo.md`。
> 合规边界：纯文档，不进入 FNV-1a 状态哈希、不进入 `SNAPSHOT_VERSION` 快照、不含任何资产或本机绝对路径（ADR 0001 / ADR 0002 / CODEBUDDY.md §6）。

## 格式约定

1. **三分判据**：能从仓库 / 本机 / 只读参考项目查到的事实，自己查并给结论，不占用户注意力；查得到候选与依据的，先给「推荐 + 依据 + 代价 + 备选」再请用户拍板；只在用户脑子里的（偏好、验收线、拍板权）才问。
2. **证据锚**：每条记录 MUST 带可核验锚点 —— `file:line`、`git` commit、artifacts 中明确记载的用户拍板、或命令输出。**无锚点记作「待确认」，MUST NOT 写成「用户已确认」**。
3. **不拿沉默当授权**：用户未明确表态 = 未拍板；「采纳推荐」须有明确记录。
4. **只记三类**：拍板决策（含被否备选与理由）、承重约束（支撑多个决策的前提，逐条带锚）、待确认项。**不写实现细节、不复述 `design.md`、不做流水账**。
5. **停止条件**：承重约束逐条站稳（有锚）且待确认项清空或显式豁免；不以「问完预设问题 / 问了 N 轮」当收敛。
6. **可裁剪**：目标与方向已清楚的小改动可省略，但 MUST 在文件内写「## 省略说明」并给出理由；范围 / 方案澄清、事实核对、决定确认三件事不可省。

## 骨架

```markdown
# 决策纪要 — `<change-name>`

> 取料纪律：基于仓库 artifacts 回填；「拍板」项须有明确记载，找不到的一律进「待确认项」，不把 AI 事后归纳写成「用户已确认」。
> 合规边界：纯文档，不进状态哈希 / 快照、不含资产。

## 承重约束（逐条带锚）

| # | 约束 | 证据锚 |
|---|---|---|
| C1 | <支撑多个决策的前提> | `<file:line>` / `<commit>` / `<命令输出>` |

## 拍板决策（含被否备选与理由）

- **P1 <决定>**。锚 `<file:line>` 或用户明确拍板记录。被否：<备选及否决理由>。

## 被否方向台账

- **R1 <方向>** → <否决依据>；若前提后续变化 MUST 整体重估，不沿用旧否决。

## 待确认项（如实标注，不冒充已拍板）

- <未决事项> → 待谁拍板 / 待什么证据。

## 停止条件（追加阶段 / 归档前）

1. 承重约束逐条仍有证据锚、无一条被本轮改动证伪。
2. 待确认项已清空或显式豁免。
3. 不以「预设问题问完」「问了 N 轮」当收敛。
```

> 诚实边界：本模板提供的是**结构性改善，不是机械保证**；机械可验的只有「纪要存在且必填小节非空」，它不能证明发生过对抗拷问。`openspec validate` 与 `verify_all.py` 当前都不校验本文件，约束靠 `rules.proposal` 注入与 `critic` 人工核对。
