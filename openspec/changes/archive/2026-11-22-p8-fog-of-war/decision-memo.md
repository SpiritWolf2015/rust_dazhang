## 拍板决策（含被否备选与理由）

- **P1 推荐 纯表现层只读派生、`w3-core` 零权威状态改动（理想零 diff）、`SNAPSHOT_VERSION` / `SIM_VERSION` / `PROTOCOL_VERSION` 全部保持 7 不 bump、golden hash `0x940cb016f6630f1e` 不变，待规格门 Q1 由用户拍板**。**锚**：本轮无用户拍板记录（「本轮授权为直到规格门再请你拍板」），推荐值来自 R2 / R3 / R4（R10.5）/ R6 / R13 / R14 / R17 / R18 / R19 / R20 / R21 / R22 / R23 / R24 / R25 与 `design.md` 单一推荐 / 判定 1–6。**MUST NOT 写成「用户已确认 / 已拍板」、不拿沉默当授权**；拍板结果若与推荐不同 MUST 按 `CODEBUDDY.md §8` 同步回查四件套、由 `spec-steward` 修订后重走规格门。**被否备选**：① **改内核新增权威状态（fog 网格进哈希 / 快照 / `first_difference()`）**——与 R10.5 / §0.3 T3 / 路线图 `:129` 正面冲突、按 `:131` 须走 ADR 0002 全套（+ bump 8 + golden hash 重取 + ADR 复核），MUST 回用户拍板触发 §8 规格门；`vera20k@305ea3a75 src/sim/world/world_hash.rs:4,687-688,589-591,1488-1497` fog 进哈希正是此路线、已登记为「对照差异、明确不借鉴」（R28 / `design.md`「## 对照差异」）；② **表现层假迷雾、无已探索层（只做圆形黑幕、不累积探索）**——降级验收、不满足 R10.1「探索后地形保留」与 `:129`「已探索层」，MUST NOT 静默采用，若用户明确拍板降级须记为被否 / 降级决策 + 已知限制、不冒充完整验收；③ **视野半径 / 昼夜常量塞进 `w3-core::FrozenDefinitions` 却声称 golden hash 不变**——ADR 0002 复核记录 P8.5a–d 证实 `defs_hash` / `content_hash` 变会改 golden hash 基线、自相矛盾，MUST NOT 采用，若确需进定义层须如实重取基线并 bump（回到备选 ① 的拍板）。**本 change 方向与 P8.5a–d 相反**（后者逐期 bump 3→7 / 新增权威状态 / 重取 golden hash），MUST NOT 沿用其「新增权威状态 / bump 8 / proto tag 46 起 / golden hash 重取」口径。
