> 规格门拍板结论（已定案）：本 change 已由用户 2026-11-24 经 `AskUserQuestion` 在规格门逐条拍板定案（`critic` 规格门报告 `blocker: 0`、建议放行到由人拍板），四件套 + `decision-memo.md` 按最终口径同步收敛为「已批准规格态」，不再有「按【推荐】成文 / 待规格门拍板」措辞。**Q1 = 改选备选「按本机导出 SLK 经典具名清单逐项对齐」**（原推荐「四族各一套完整原创合成技能体系」降为被否备选）；**Q1↔Q2 调和 = 清单对齐 SLK、标识仍合成**（不引入四字符 ID → `DefId` 映射层）；**全量边界 = 四族英雄技能全量 + 各族代表性单位 / 道具技能**，中立英雄 / 野怪 / 全部单位技能顺延、标已知限制；**Q5 = `SNAPSHOT_VERSION` / `SIM_VERSION` / `PROTOCOL_VERSION` 三者同步 8→9**；**Q2 / Q3 / Q4 / Q6 / Q7 / Q8 / Q10 全部按推荐**；**Q9 / Q-A 为已拍板流程约束、非待拍板项**（Q-A 活文档细化仍按已拍板顺序在 apply 阶段由 `docs-owner` 落定，本期正文零改动）；**9 条 B 类 residual 按用户拍板「批准前修订再锁定」逐条吸收**。`## 规格门` 保持 `status: pending`，`status: approved` + `fingerprint` + `approved_by` + `date` 由 leader 交付后回填、不 self-approve；本次修订不触发 `CODEBUDDY.md §8` 规格解锁、不重走规格门。

## Why

当前 `w3-core` 技能层只有 4 类 `EffectKind`（`Damage` / `Heal` / `BuffStat` / `Stun`，`gameplay.rs:283-288`）、单体实体目标 `Cast`（`gameplay.rs:1323-1327`）与一次性 `execute_cast`（`sim_match.rs:1316`），无法表达经典技能原语（持续 AOE / 召唤 / 光环 / 被动 proc / 变身 / 点目标 / buff 分类移除 / 链接弹射 / 随机）；`crates/w3-client/src/melee/defs.rs:794-797` 的「MUST NOT 新增 `EffectKind` 变体 / 命令变体 / JASS VM（N5）」是 P8.1 当期 change 内约束、非永久门禁。按 1.0 范围 **S3**（4 种族功能做完，`WC3-MELEE-RULES.md:27`）与业务规则 **R6**（英雄技能 / 等级 / 6 级大招，`:163-171`）、**R7.6**（道具 abilList 走既有 `EffectDef` 组合、MUST NOT 直接执行任意 JASS，`:182`）、R2 / R12 / R10.5，本期把「技能系统」立项为独立范围项，做「四族全量 + bump 9 全套」确定性契约；其余 1.0 范围 S1 / S2 / S4 / S5 / S6 不新增、不删减。**明确不做**：N1–N6，尤其 **N2 地图编辑器 / N3 RPG 自定义地图 / N5 JASS·wtg 触发器 VM**（`:43-46`）；AI 全量行为顺延 P12、本期不做 AI 自主施法。

## What Changes

- **BREAKING**：新增技能系统权威运行态，`SNAPSHOT_VERSION` / `SIM_VERSION` / `PROTOCOL_VERSION` 由 8 bump 到 9（Q5 已由用户规格门拍板：三者同步）；旧 v8 快照 / 回放 / 包按 `UnsupportedVersion` / `SimVersionMismatch` / `VersionMismatch` + relay `Reject` 明确拒绝，不提供跨版本迁移（ADR 0002 §7 / ADR 0005 §3）。
- **Q1 已拍板定案：按本机导出 SLK 清单逐项对齐、标识仍合成原创**。新增 `ability-system` capability：四族技能**清单**逐项按本机导出 `UnitAbilities.heroAbilList` / `abilList` + `AbilityData`（`code` / `race` / `hero` / `levels` / `reqLevel` 列）核对后，**人工固化成编译期常量表**进 `FrozenDefinitions`；本期范围 = 四族英雄技能全量（经典清单结构：每族 4 英雄 × 4 技能 = 英雄 3 普通 + 1 个 6 级大招，含技能点 / 等级 / 学习 / 升级）+ 各族代表性单位 / 道具技能（道具技能经既有 `EffectDef` 组合走 R7.6），中立英雄 / 野怪 / 全部单位技能顺延、标已知限制。内部仍用合成原创 `DefId` 作键（沿用 `ABILITY=10` / 英雄 `11–14` 并扩四族）、**不引入四字符 ID → `DefId` 映射层**、数值一律 `[待核]`、名称合成原创不冒充经典具名技能、SLK 四字符 ID 只作核对依据、**不进权威状态 / 状态哈希 / 快照 / 不入库**（`WC3-MELEE-RULES.md:124,351`、ADR 0001 / 0002 / 0004、`crates/w3-client/src/melee/defs.rs:1-6` 纯编译期零文件 IO）。**两层张力显式写清、避免自相矛盾**：对齐的是**清单条目与分类**（哪些技能、每族几个、英雄 3 普通 + 1 大招、单位 / 道具技能），不是照搬经典名称 / rawcode / 数值；「清单结构 / 条目逐项对齐经典具名技能」与「合成原创命名、不冒充经典具名技能 / 数值」是两个层次。「每族 4 英雄 × 4 技能」是经典清单结构口径、不是从本机导出表粗统计推得的精确条目数，实际清单条目数在 apply 阶段人工核对后如实登记、不臆造「四族全量 = 某精确数字」；清单规模元数据只登记规模与分类、不写任何具体 rawcode / 技能名 / 数值（见 `design.md`「清单规模事实锚」与 D1），清单逐项固化由 apply 阶段人工核对（数值 `[待核]`、不静默改规则，`WC3-MELEE-RULES.md §14`）。
- 新增最小必要 `EffectKind` 行为原语集（持续 AOE / zone、召唤、光环受益集、被动 proc 订阅、变身 / 状态切换、点目标、buff 分类移除、链接弹射、随机消费）与一个 `BehaviorCatalog` 式注册表（OCP：注册新行为 = 扩展而非散落分支），对应 Data / Logic / Present 分层（参考对照结论 G1 / G5）。
- 施法走 `GameplayCommandKind::Cast`（新增技能命令按「只追加 kind 码 / proto tag」纪律扩展点目标 / 范围 / 方向）；建造走 `GameplayCommandKind::Train { is_building: true }`；攻击 / 移动 / 停止走 `CommandKind::{Attack, Move, Stop}`（`command.rs:11-49`）；MUST NOT 写成不存在的 `GameplayCommandKind::Attack` / `::Build`（结论 G8）。
- 新增权威运行态四处同步（`compute_state_hash` / `capture_snapshot` / `restore_snapshot` / `first_difference`）进 FNV-1a 状态哈希与由 `SNAPSHOT_VERSION`（bump 9）定义的快照；定义层冻结常量经 `compute_defs_hash` 进 `defs_hash` / `content_hash` 快照头部，与新增权威运行态严格区分（ADR 0002 §6-8 / `0002-determinism.md:111,115,117`）。
- 沿用单条 match-owned 整数 LCG + 显式 `rng_draws` 编码（P8.5c 先例 `0002-determinism.md:113`），消费顺序进快照 / `first_difference`；golden hash 按 v9 新实现如实重取、不沿用 `0x0b53a047b1f8e5e0`；`w3net.proto` 只追加 tag、`reserved 14 to 32` 保持。
- 表现层只读派生、不反写权威状态（ADR 0002 §5 / R10.5）；本期不含 AI 自主施法、不改 `AiScript` 现有取 `Cast` 目标 ID 的只读夹具。
- **流程约束（Q-A，已拍板、非待拍板项）**：`docs/references/WC3-MELEE-RULES.md` 的范围细化（S3 下细化「英雄 / 单位技能全量」+ 附录「规则 → 实现覆盖对照」新增 R6 技能独立行 + §15 变更记录追加一条，不新增 S 编号）与 P11 同批，按用户 2026-11-24 已拍板顺序（规格门批准记录由 leader 回填后）在 apply 阶段由 `docs-owner` 落定；本期对活文档**正文零改动**，见 `tasks.md` 复选框与 `design.md`「Q-A 活文档细化」决策（按 §14 第 2 条注明 2026-11-24 日期与依据，`WC3-MELEE-RULES.md:415-421`）。
